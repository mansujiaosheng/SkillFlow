# 通用项目上下文 Skill

## 通用执行约束

- 本 Skill 面向任意软件项目、数据项目、自动化项目或 AI 协作项目，不绑定具体业务、仓库名、目录名、团队名或技术栈。
- 回答或修改前，必须先基于当前仓库的真实文件、用户本次目标和已有约定判断；禁止臆造不存在的目录、接口、配置、数据或团队规则。
- 用户指令与仓库事实、公开接口、安全底线、可回滚原则或已明确的验收标准冲突时，必须先指出冲突点和风险，再给出更稳妥的替代方案。
- 用户坚持继续时，也只能执行可回滚、可测试、不会破坏公开接口和安全底线的部分；禁止删除测试、伪造结果、绕过保护机制或扩大任务范围。
- 多个方案都可行时，必须选择影响范围更小、依赖更少、测试更明确、回滚更容易的方案。

## 功能定位

用于在开发、审查或回答前恢复项目上下文，避免在没有读取项目事实的情况下生成不符合仓库现状的方案。

## 必读信息

根据仓库实际情况，优先读取以下类型文件：

1. 项目说明：`README*`、`docs/*`、项目介绍文档。
2. AI 协作记忆：`AGENTS.md`、`CLAUDE.md`、`.cursor/rules/*`、项目自定义规则。
3. 架构说明：架构图、模块说明、ADR/RFC、设计文档。
4. 入口文件：CLI 入口、Web 入口、服务启动入口、包导出文件。
5. 配置文件：依赖、环境变量示例、构建配置、CI 配置。
6. 测试目录：测试命名、fixtures、集成测试入口。

## 项目上下文恢复顺序

1. 用一句话描述项目目标。
2. 列出主要输入、处理流程、输出。
3. 确认关键目录和模块职责。
4. 确认公共接口、配置和数据模型。
5. 确认测试、CI、发布或部署方式。
6. 标记不确定或需要人工确认的点。

## 输出模板

```markdown
## 项目一句话说明

## 主要数据流 / 调用流

## 目录与模块职责

## 关键接口与配置

## 开发前必须确认的事实

## 不确定项
```

## 通用输出要求

- 先给结论，再给步骤。
- 涉及命令时，给出可直接复制的命令。
- 涉及代码改动时，说明影响范围、需要补充的测试、是否需要更新文档或变更记录。
- 信息不足时，指出需要读取的项目文件或需要确认的事实；不得用猜测替代项目事实。
