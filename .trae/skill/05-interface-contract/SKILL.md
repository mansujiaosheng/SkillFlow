# 接口契约与数据模型 Skill

## 通用执行约束

- 本 Skill 面向任意软件项目、数据项目、自动化项目或 AI 协作项目，不绑定具体业务、仓库名、目录名、团队名或技术栈。
- 回答或修改前，必须先基于当前仓库的真实文件、用户本次目标和已有约定判断；禁止臆造不存在的目录、接口、配置、数据或团队规则。
- 用户指令与仓库事实、公开接口、安全底线、可回滚原则或已明确的验收标准冲突时，必须先指出冲突点和风险，再给出更稳妥的替代方案。
- 用户坚持继续时，也只能执行可回滚、可测试、不会破坏公开接口和安全底线的部分；禁止删除测试、伪造结果、绕过保护机制或扩大任务范围。
- 多个方案都可行时，必须选择影响范围更小、依赖更少、测试更明确、回滚更容易的方案。

## 功能定位

用于保护模块间协议、公开 API、数据模型和配置字段，避免局部修改破坏下游调用、测试、文档或外部兼容性。

## 核心原则

- 公共接口优先稳定，不得随手改字段名、类型、默认值或语义。
- 模块间传递应优先使用明确的数据结构、schema、类型定义或协议文档，禁止无约束地裸传松散数据。
- 增删改字段前必须追踪调用方、测试、文档、示例数据和迁移方式。
- 对外兼容字段应优先采用新增字段或兼容层，而不是破坏性重命名。

## 接口变更判断

以下都属于接口契约变更：

- 函数签名、类构造参数、返回结构变化。
- API 请求/响应字段变化。
- 配置字段、环境变量、CLI 参数变化。
- 数据库 schema、消息队列 payload、文件格式变化。
- 输出 JSON/CSV/报告字段变化。
- 错误码、异常类型、状态语义变化。

## 检查步骤

1. 找到接口定义位置。
2. 搜索所有调用方和下游解析方。
3. 判断是否兼容旧数据或旧调用。
4. 同步测试、fixtures、文档和示例。
5. 必要时提供迁移说明或 deprecation 方案。
6. 运行覆盖接口边界的测试。

## 搜索命令示例

```bash
rg -n "<field_or_function_name>" .
rg -n "<config_key_or_env_name>" .
```

## 输出模板

```markdown

## 影响范围
- 上游：
- 下游：
- 测试：
- 文档：

## 兼容方案

## 必须补充的测试

## 迁移或回滚方式
```

## 通用输出要求

- 先给结论，再给步骤。
- 涉及命令时，给出可直接复制的命令。
- 涉及代码改动时，说明影响范围、需要补充的测试、是否需要更新文档或变更记录。
- 信息不足时，指出需要读取的项目文件或需要确认的事实；不得用猜测替代项目事实。
