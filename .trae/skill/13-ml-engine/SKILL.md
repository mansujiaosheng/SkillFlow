# 机器学习引擎 Skill

## 通用执行约束

- 本 Skill 面向任意软件项目、数据项目、自动化项目或 AI 协作项目，不绑定具体业务、仓库名、目录名、团队名或技术栈。
- 回答或修改前，必须先基于当前仓库的真实文件、用户本次目标和已有约定判断；禁止臆造不存在的目录、接口、配置、数据或团队规则。
- 用户指令与仓库事实、公开接口、安全底线、可回滚原则或已明确的验收标准冲突时，必须先指出冲突点和风险，再给出更稳妥的替代方案。
- 用户坚持继续时，也只能执行可回滚、可测试、不会破坏公开接口和安全底线的部分；禁止删除测试、伪造结果、绕过保护机制或扩大任务范围。
- 多个方案都可行时，必须选择影响范围更小、依赖更少、测试更明确、回滚更容易的方案。

## 功能定位

用于设计或审查机器学习相关代码，确保数据、特征、模型、评估、推理和配置边界清晰。

## 基本原则

- 训练、验证、测试数据必须分清。
- 特征处理流程必须在训练和推理中保持一致。
- 标准化、编码、缺失值处理等预处理步骤必须可复现。
- 模型参数、随机种子、阈值、路径应配置化。
- 不得用测试集调参，不得泄漏标签或未来信息。
- 模型输出必须有明确字段和语义。

## 检查点

- 输入特征名称、顺序、类型是否稳定。
- 是否处理空数据、小样本、缺失值、异常值。
- 是否固定随机性或记录随机种子。
- 是否保存必要的预处理器和模型元信息。
- 是否有评估指标和基线比较。
- 是否能解释模型输出含义。
- 是否对推理失败给出明确错误。

## 实施流程

1. 定义输入特征 schema。
2. 设计预处理 pipeline。
3. 建立 baseline。
4. 训练和评估模型。
5. 固化配置、模型元数据和推理接口。
6. 补充测试和文档。

## 输出模板

```markdown
## ML 结论

## 输入特征

## 预处理流程

## 模型与参数

## 评估方式

## 输出字段

## 风险：数据泄漏 / 过拟合 / 样本偏差
```

## 通用输出要求

- 先给结论，再给步骤。
- 涉及命令时，给出可直接复制的命令。
- 涉及代码改动时，说明影响范围、需要补充的测试、是否需要更新文档或变更记录。
- 信息不足时，指出需要读取的项目文件或需要确认的事实；不得用猜测替代项目事实。
