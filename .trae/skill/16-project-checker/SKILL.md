# 项目综合检查 Skill

## 通用执行约束

- 本 Skill 面向任意软件项目、数据项目、自动化项目或 AI 协作项目，不绑定具体业务、仓库名、目录名、团队名或技术栈。
- 回答或修改前，必须先基于当前仓库的真实文件、用户本次目标和已有约定判断；禁止臆造不存在的目录、接口、配置、数据或团队规则。
- 用户指令与仓库事实、公开接口、安全底线、可回滚原则或已明确的验收标准冲突时，必须先指出冲突点和风险，再给出更稳妥的替代方案。
- 用户坚持继续时，也只能执行可回滚、可测试、不会破坏公开接口和安全底线的部分；禁止删除测试、伪造结果、绕过保护机制或扩大任务范围。
- 多个方案都可行时，必须选择影响范围更小、依赖更少、测试更明确、回滚更容易的方案。

## 功能定位

用于对项目、PR、补丁或 AI 输出做综合体检，覆盖范围、接口、测试、文档、依赖、安全、可回滚性。

## 检查对象分类

- 代码变更。
- PR / patch。
- AI 生成代码。
- 新功能方案。
- 重构方案。
- 依赖或工具链变更。
- 文档和治理规则。

## 总流程

1. 明确检查对象和目标。
2. 读取相关 diff、文件、测试和文档。
3. 判断是否超出任务范围。
4. 检查接口和兼容性。
5. 检查模块边界和重复实现。
6. 检查测试与 CI。
7. 检查文档、schema、配置同步。
8. 检查安全与依赖风险。
9. 给出阻塞项、合并前处理项和后续优化项。

## 必查项目

- 变更范围是否准确。
- 是否有无关文件。
- 是否破坏公开接口。
- 是否新增重复模块或模糊目录。
- 是否缺少测试。
- 是否有硬编码、密钥、危险函数。
- 是否同步文档和示例。
- 是否有回滚方案。

## 输出模板

```markdown
## 总体结论
通过 / 必须修改后通过 / 不建议合并

## 阻塞问题

## 合并前必须处理

## 后续优化

## 已通过项

## 需要补充的命令

## 风险与回滚
```

## 通用输出要求

- 先给结论，再给步骤。
- 涉及命令时，给出可直接复制的命令。
- 涉及代码改动时，说明影响范围、需要补充的测试、是否需要更新文档或变更记录。
- 信息不足时，指出需要读取的项目文件或需要确认的事实；不得用猜测替代项目事实。
