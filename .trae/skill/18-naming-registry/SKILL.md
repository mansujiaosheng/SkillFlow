# 命名登记与冲突检查 Skill

## 通用执行约束

- 本 Skill 面向任意软件项目、数据项目、自动化项目或 AI 协作项目，不绑定具体业务、仓库名、目录名、团队名或技术栈。
- 回答或修改前，必须先基于当前仓库的真实文件、用户本次目标和已有约定判断；禁止臆造不存在的目录、接口、配置、数据或团队规则。
- 用户指令与仓库事实、公开接口、安全底线、可回滚原则或已明确的验收标准冲突时，必须先指出冲突点和风险，再给出更稳妥的替代方案。
- 用户坚持继续时，也只能执行可回滚、可测试、不会破坏公开接口和安全底线的部分；禁止删除测试、伪造结果、绕过保护机制或扩大任务范围。
- 多个方案都可行时，必须选择影响范围更小、依赖更少、测试更明确、回滚更容易的方案。

## 功能定位

用于统一项目概念命名，避免同一概念多个名字、不同概念共用一个名字、文件名和模块名含义模糊。

## 基础命名规则

- 名称必须表达职责、对象和边界。
- 同一概念只保留一种命名。
- 不同层级命名要保持一致：代码、配置、schema、文档、测试。
- 避免 `manager`、`handler`、`processor`、`helper` 等低信息量词，除非项目已有严格语义。
- 文件名、类名、函数名不得只反映实现细节而不反映业务或职责。

## 检查流程

```bash
rg -n "<candidate_name>|<old_name>|<similar_name>" .
find . -iname "*<keyword>*"
```

检查：

1. 是否已有同名或近义实现。
2. 是否与已有概念冲突。
3. 是否需要同步配置、schema、文档、测试。
4. 是否需要加入命名登记表。

## 命名登记表示例

```markdown
| 概念 | 统一命名 | 禁止/避免使用 | 说明 |
|---|---|---|---|
| <concept> | <canonical_name> | <bad_names> | <meaning> |
```

## 输出模板

```markdown
## 命名结论

## 推荐命名

## 不推荐命名

## 冲突检查结果

## 需要同步的位置
```

## 通用输出要求

- 先给结论，再给步骤。
- 涉及命令时，给出可直接复制的命令。
- 涉及代码改动时，说明影响范围、需要补充的测试、是否需要更新文档或变更记录。
- 信息不足时，指出需要读取的项目文件或需要确认的事实；不得用猜测替代项目事实。
