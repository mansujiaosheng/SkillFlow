# 任务登记与防重复开发 Skill

## 通用执行约束

- 本 Skill 面向任意软件项目、数据项目、自动化项目或 AI 协作项目，不绑定具体业务、仓库名、目录名、团队名或技术栈。
- 回答或修改前，必须先基于当前仓库的真实文件、用户本次目标和已有约定判断；禁止臆造不存在的目录、接口、配置、数据或团队规则。
- 用户指令与仓库事实、公开接口、安全底线、可回滚原则或已明确的验收标准冲突时，必须先指出冲突点和风险，再给出更稳妥的替代方案。
- 用户坚持继续时，也只能执行可回滚、可测试、不会破坏公开接口和安全底线的部分；禁止删除测试、伪造结果、绕过保护机制或扩大任务范围。
- 多个方案都可行时，必须选择影响范围更小、依赖更少、测试更明确、回滚更容易的方案。

## 功能定位

用于让每个开发任务有明确范围、负责人、分支、PR、验收标准和禁止修改范围，减少重复开发和无关变更。

## 基本原则

- 一项任务对应一个明确目标。
- 一个分支只解决一个任务。
- 一个 PR 不混入多个无关任务。
- 开发前先查 Issue、任务板、分支、PR、已有代码。
- 任务登记必须能指导 review。

## 任务登记字段

```markdown
| Issue | 任务 | 负责人 | 模块 | 分支 | 新增文件 | 修改文件 | 接口影响 | 测试 | 状态 |
|---|---|---|---|---|---|---|---|---|---|
```

## 开发前检查

```bash
git fetch --all
git branch -a
gh issue list
gh pr list
rg -n "<keyword>|<function>|<concept>" .
```

按项目实际工具替换 GitHub CLI。

## 输出模板

```markdown
## 任务登记结论

## 任务范围

## 允许修改

## 禁止修改

## 需要复用的已有实现

## 分支与 PR 关系

## 验收标准
```

## 通用输出要求

- 先给结论，再给步骤。
- 涉及命令时，给出可直接复制的命令。
- 涉及代码改动时，说明影响范围、需要补充的测试、是否需要更新文档或变更记录。
- 信息不足时，指出需要读取的项目文件或需要确认的事实；不得用猜测替代项目事实。
