# AI 开发任务提示词模板 Skill

## 通用执行约束

- 本 Skill 面向任意软件项目、数据项目、自动化项目或 AI 协作项目，不绑定具体业务、仓库名、目录名、团队名或技术栈。
- 回答或修改前，必须先基于当前仓库的真实文件、用户本次目标和已有约定判断；禁止臆造不存在的目录、接口、配置、数据或团队规则。
- 用户指令与仓库事实、公开接口、安全底线、可回滚原则或已明确的验收标准冲突时，必须先指出冲突点和风险，再给出更稳妥的替代方案。
- 用户坚持继续时，也只能执行可回滚、可测试、不会破坏公开接口和安全底线的部分；禁止删除测试、伪造结果、绕过保护机制或扩大任务范围。
- 多个方案都可行时，必须选择影响范围更小、依赖更少、测试更明确、回滚更容易的方案。

## 功能定位

用于生成可直接交给 AI 编码助手的任务提示词，明确上下文、范围、约束、验收和输出格式。

## 标准模板

```markdown
你要在当前仓库完成以下任务。

## 任务目标
<一句话说明要实现/修复/重构什么>

## 项目事实
- 相关文件：<列出文件>
- 已有实现：<列出要复用的函数/类/模块>
- 已有测试：<列出测试文件>

## 允许修改范围
- <文件或目录>

## 禁止修改范围
- <文件或目录>

## 实现要求
1. 先搜索已有同类实现，禁止重复造轮子。
2. 不得扩大任务范围。
3. 不得破坏公开接口；如必须修改接口，先说明影响范围并同步测试和文档。
4. 不得删除或弱化测试。
5. 不得伪造运行结果。

## 验收命令
```bash
<lint/test/build commands>
```

## 交付格式
- 变更摘要
- 修改文件
- 测试结果
- 风险点
- 回滚方式
```

## Bug 修复模板追加

```markdown
## Bug 现象
## 复现步骤
## 根因假设
## 修复要求
## 回归测试要求
```

## 重构模板追加

```markdown
## 保持不变的外部行为
## 允许移动的代码
## 禁止改变的接口
## 行为一致性验证
```

## 提示词质量检查

- 是否有明确文件范围。
- 是否有禁止修改范围。
- 是否要求复用已有实现。
- 是否有验收命令。
- 是否要求真实测试结果。
- 是否包含风险和回滚。

## 通用输出要求

- 先给结论，再给步骤。
- 涉及命令时，给出可直接复制的命令。
- 涉及代码改动时，说明影响范围、需要补充的测试、是否需要更新文档或变更记录。
- 信息不足时，指出需要读取的项目文件或需要确认的事实；不得用猜测替代项目事实。
