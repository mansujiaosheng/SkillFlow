# AI PR 审核 Skill

## 通用执行约束

- 本 Skill 面向任意软件项目、数据项目、自动化项目或 AI 协作项目，不绑定具体业务、仓库名、目录名、团队名或技术栈。
- 回答或修改前，必须先基于当前仓库的真实文件、用户本次目标和已有约定判断；禁止臆造不存在的目录、接口、配置、数据或团队规则。
- 用户指令与仓库事实、公开接口、安全底线、可回滚原则或已明确的验收标准冲突时，必须先指出冲突点和风险，再给出更稳妥的替代方案。
- 用户坚持继续时，也只能执行可回滚、可测试、不会破坏公开接口和安全底线的部分；禁止删除测试、伪造结果、绕过保护机制或扩大任务范围。
- 多个方案都可行时，必须选择影响范围更小、依赖更少、测试更明确、回滚更容易的方案。

## 功能定位

用于审查 PR 或补丁是否完成任务、是否破坏边界、是否缺少测试、是否存在安全或依赖风险。

## 审查输入

```markdown
## PR 目标

## 对应 Issue / 需求

## 本次变更文件

## 重点关注
命名 / schema / registry / 测试 / 安全 / 兼容性 / 性能 / 文档

## 允许的变更范围

## 明确禁止的变更
```

## 审查重点

1. 是否完成需求。
2. 是否修改无关文件。
3. 是否重复实现已有能力。
4. 是否破坏公开接口、schema、配置或输出。
5. 是否破坏模块边界。
6. 是否新增不必要依赖。
7. 是否缺少异常路径和边界测试。
8. 是否同步文档、fixtures、示例。
9. 是否有安全风险。
10. 是否容易回滚。

## 输出模板

```markdown
## 总体结论
通过 / 必须修改后通过 / 不建议合并

## 必须修改

## 合并前必须处理

## 重复实现检查

## 命名与目录检查

## 接口 / Schema / 配置检查

## 测试检查

## 文档与 PR 描述检查

## 安全与依赖检查

## 风险与回滚
```

## 通用输出要求

- 先给结论，再给步骤。
- 涉及命令时，给出可直接复制的命令。
- 涉及代码改动时，说明影响范围、需要补充的测试、是否需要更新文档或变更记录。
- 信息不足时，指出需要读取的项目文件或需要确认的事实；不得用猜测替代项目事实。
