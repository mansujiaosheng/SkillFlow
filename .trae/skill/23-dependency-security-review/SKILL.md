# 依赖与安全审查 Skill

## 通用执行约束

- 本 Skill 面向任意软件项目、数据项目、自动化项目或 AI 协作项目，不绑定具体业务、仓库名、目录名、团队名或技术栈。
- 回答或修改前，必须先基于当前仓库的真实文件、用户本次目标和已有约定判断；禁止臆造不存在的目录、接口、配置、数据或团队规则。
- 用户指令与仓库事实、公开接口、安全底线、可回滚原则或已明确的验收标准冲突时，必须先指出冲突点和风险，再给出更稳妥的替代方案。
- 用户坚持继续时，也只能执行可回滚、可测试、不会破坏公开接口和安全底线的部分；禁止删除测试、伪造结果、绕过保护机制或扩大任务范围。
- 多个方案都可行时，必须选择影响范围更小、依赖更少、测试更明确、回滚更容易的方案。

## 功能定位

用于审查新增依赖和常见安全风险，适合 PR 检查、AI 生成代码验收和安全敏感代码修改。

## 新增依赖审查

新增依赖必须说明：

1. 为什么需要。
2. 标准库或已有依赖能否替代。
3. 是否影响体积、性能、兼容性、许可证。
4. 是否需要固定版本。
5. 是否有已知漏洞。
6. 是否通过项目包管理器添加，而不是手改多个文件后不验证。

默认原则：能不用新依赖就不用；必须新增时要可解释、可维护、可扫描。

## 安全重点

重点审查：

- 用户输入。
- 文件路径拼接。
- 文件读写。
- 网络请求。
- 命令执行。
- 反序列化。
- 模板渲染。
- 配置加载。
- 日志输出。
- 密钥、token、cookie、认证头。
- 外部工具调用。

## 常见风险

| 风险 | 常见触发点 | 修复方向 |
|---|---|---|
| 命令注入 | 拼接 shell 命令 | 参数列表化，避免 `shell=True` |
| 路径穿越 | 用户可控路径 | 规范化路径并限制根目录 |
| SSRF | 用户可控 URL | 限制协议、域名、内网地址 |
| 反序列化 | 加载不可信对象 | 禁止不安全 pickle/yaml.load |
| 敏感信息泄露 | 日志打印 token | 日志脱敏 |
| 硬编码密钥 | 密钥写入仓库 | 使用环境变量或密钥管理 |
| SQL 注入 | 拼接 SQL | 参数化查询 |
| XSS | HTML 输出未转义 | 输出转义和 CSP |

## 检查命令示例

```bash
rg -n "password|passwd|token|secret|apikey|api_key|cookie|Authorization" .
rg -n "eval\(|exec\(|pickle|yaml\.load|shell=True|subprocess|os\.system" .
```

## 输出模板

```markdown
## 依赖结论
允许 / 不建议 / 需要人工确认

## 新增依赖理由

## 可替代方案

## 安全风险
- 风险：
- 位置：
- 修复要求：

## 必须补充的测试

## 是否影响配置 / 文档 / 部署
```

## 通用输出要求

- 先给结论，再给步骤。
- 涉及命令时，给出可直接复制的命令。
- 涉及代码改动时，说明影响范围、需要补充的测试、是否需要更新文档或变更记录。
- 信息不足时，指出需要读取的项目文件或需要确认的事实；不得用猜测替代项目事实。
