# 自动检查脚本与 CI 扩展 Skill

## 通用执行约束

- 本 Skill 面向任意软件项目、数据项目、自动化项目或 AI 协作项目，不绑定具体业务、仓库名、目录名、团队名或技术栈。
- 回答或修改前，必须先基于当前仓库的真实文件、用户本次目标和已有约定判断；禁止臆造不存在的目录、接口、配置、数据或团队规则。
- 用户指令与仓库事实、公开接口、安全底线、可回滚原则或已明确的验收标准冲突时，必须先指出冲突点和风险，再给出更稳妥的替代方案。
- 用户坚持继续时，也只能执行可回滚、可测试、不会破坏公开接口和安全底线的部分；禁止删除测试、伪造结果、绕过保护机制或扩大任务范围。
- 多个方案都可行时，必须选择影响范围更小、依赖更少、测试更明确、回滚更容易的方案。

## 功能定位

用于把人工规范变成机器可执行的检查脚本和 CI 闸门，降低漏检和人为执行成本。

## 可新增检查脚本类型

```text
scripts/check_all.py
scripts/check_format.py
scripts/check_tests.py
scripts/check_forbidden_names.py
scripts/check_duplicate_names.py
scripts/check_large_files.py
scripts/check_module_boundaries.py
scripts/check_schema_docs_sync.py
scripts/check_registry_sync.py
scripts/check_no_secrets.py
scripts/check_dangerous_calls.py
```

脚本名和语言以项目实际技术栈为准。

## 检查项

| 检查项 | 目的 |
|---|---|
| 格式化 | 保持统一风格 |
| 静态检查 | 发现低级错误和风格问题 |
| 单元测试 | 检查局部逻辑 |
| 集成测试 | 检查模块协作 |
| schema/docs 同步 | 防止字段漂移 |
| registry 同步 | 防止能力不可发现 |
| 重复命名 | 防止概念冲突 |
| 禁止模糊目录 | 防止架构腐化 |
| 超大文件 | 防止误提交数据或产物 |
| 跨层调用 | 防止依赖倒置 |
| 硬编码密钥 | 防止敏感信息泄露 |
| 危险函数调用 | 发现安全风险 |

## CI 最小要求

每次 PR 至少运行：

- 依赖安装或锁文件校验。
- 格式化检查。
- 静态检查。
- 单元测试。
- 必要构建或集成测试。
- 密钥扫描或危险调用扫描。

```markdown
- 检查目的：
- 失败条件：
- 是否加入 CI：

## 不应误杀的项目例外

## CI 更新要求

## 本地运行命令
```

## 通用输出要求

- 先给结论，再给步骤。
- 涉及命令时，给出可直接复制的命令。
- 涉及代码改动时，说明影响范围、需要补充的测试、是否需要更新文档或变更记录。
- 信息不足时，指出需要读取的项目文件或需要确认的事实；不得用猜测替代项目事实。
