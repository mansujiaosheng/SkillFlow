# SkillFlow Schema

SkillFlow uses `.skillflow/` as the editable source of truth. Generated files such as
`skills/<folder>/SKILL.md` and `workflow.md` are derived outputs and can be regenerated from
the source JSON.

## Source Files

- `.skillflow/project.json`: project metadata, including `schemaVersion`, `projectId`, `name`,
  `description`, `targetPlatforms`, `createdAt`, and `updatedAt`.
- `.skillflow/workflow.json`: the React Flow graph. `nodes` describe Skill, global rule, check,
  export, and note nodes. `edges` describe semantic relationships between nodes.
- `.skillflow/nodes.json`: compatibility mirror of `workflow.nodes` for tools that only need node
  data.
- `.skillflow/rules.json`: project-level rule blocks.
- `.skillflow/resources.json`: project-level reusable resources. Resources can be scripts,
  references, assets, or attachments.
- `.skillflow/settings.json`: UI and generation settings, including template mode, ordered template
  sections, and advanced Markdown template.
- `.skillflow/lint-report.json`: latest lint result. This is generated by the TypeScript linter and
  persisted by the Rust backend.

## Core Data

`SkillNodeData` is the editable payload for each flow node. Important fields include `nodeType`,
`name`, `folder`, `description`, `whenToUse`, `inputs`, `outputs`, `steps`, `requires`, `forbids`,
`checks`, `fallbacks`, `rules`, `resourceRefs`, node-local resources, and Markdown edit mode.

`WorkflowEdgeData` describes how two nodes relate:

- `relation`: `before`, `depends_on`, `handoff`, `review_by`, `fallback_to`, or `parallel_with`.
- `description`: human-readable explanation.
- `handoffData`: data passed from source node to target node.
- `required`: whether the relationship is mandatory.
- `note`: extra note for the edge.

`NodeResource` describes a reusable or node-local resource:

- `kind`: `script`, `reference`, `asset`, or `attachment`.
- `name`: display name.
- `path`: project-relative path or URL.
- `resourceType`: language, file type, or media type.
- `description`: purpose. Scripts are only referenced, not executed by SkillFlow.

## Flowchart Role

The flowchart is not decoration. It is the main entry point for understanding a Skill system:

- Nodes explain individual Skills or canvas notes.
- Edges explain dependencies, handoffs, reviews, fallbacks, and parallel work.
- Resource references explain which scripts, documents, assets, or attachments a Skill needs.
- `workflow.md` summarizes the whole graph so generated Skill packs remain readable outside the UI.

## Generation Boundary

TypeScript is the only source for generation and lint business logic:

- `generateSkillMarkdown` and `generateAllSkillMarkdown` create `SKILL.md` content.
- `generateWorkflowMarkdown` creates `workflow.md`.
- `lintProject` creates the lint report.

Rust commands only create/open/save project files, import resources, write generated files, and
persist lint reports. Rust does not interpret templates, run lint rules, or execute scripts.
